# Bug 72 — SIGABRT в RenderThread на простое: «drawRenderNode called on a context with no surface!»

> **Статус:** 🔬 ОТКРЫТ, форензика собрана, воспроизведение не найдено
> **Версия:** 0.8 (23), debug-сборка · **Устройство:** Headwolf Titan 1 (Android 16 / SDK 36)
> **Найден:** 2026-07-28 агентом — в кольцевом буфере logcat при разборе прогона Ш0 (`plans/21`).
> Криник об этом краше НЕ сообщал; неизвестно, заметил ли он его вообще.

---

## Симптом

Приложение аварийно завершается **нативным сигналом** (не Java-исключением) во время ПРОСТОЯ —
без действий пользователя, спустя долгое время после остановки эфира.

```
07-28 21:08:21.898 F/libc: Fatal signal 6 (SIGABRT), code -1 (SI_QUEUE)
                            in tid 10022 (RenderThread), pid 9991 (niks.kcam.debug)
Abort message: 'drawRenderNode called on a context with no surface!'
Process uptime: 1416s
backtrace:
  #04 libhwui.so android::uirenderer::skiapipeline::SkiaOpenGLPipeline::getFrame()+48
  #05 libhwui.so android::uirenderer::renderthread::CanvasContext::draw(bool)+280
  #06 libhwui.so DrawFrameTask::postAndWait()
  #07 libhwui.so RenderThread::threadLoop()+772
```

Стек **целиком системный** (HWUI/Skia) — нашего кода в нём нет. Это означает: системный рендер-тред
получил задачу нарисовать кадр в `CanvasContext`, у которого поверхность уже отобрана.

## Хронология (по логу приложения и logcat)

| Время | Событие |
|---|---|
| ~20:44:45 | старт процесса (вычислено: 21:08:21 − uptime 1416 с) |
| 20:46:58.676 | `[RtmpStreamer] liveTicker: эфир завершён, тикер остановлен` — **последняя запись приложения** |
| 20:47 – 21:08 | **22 минуты тишины в логе приложения** (активности нет) |
| 21:08:21.898 | SIGABRT в RenderThread |
| 21:08:25.068 | `USB event: DeviceAttached(EMEET Piko+)` — уже в НОВОМ процессе |

Подключение вебки произошло **через 3 секунды ПОСЛЕ** краша, то есть причиной быть не могло; скорее
наоборот — USB-интент поднял приложение заново (у него есть intent-filter на USB_DEVICE_ATTACHED).

## Что известно и что нет

**Известно:**
- Краш нативный, в системном рендер-треде, при простое, после завершения эфира.
- Классический смысл `drawRenderNode … no surface` — кадр рисуется, когда `Surface` окна уже
  уничтожена (экран погас, окно ушло, activity destroyed), а источник инвалидаций продолжает
  дёргать отрисовку.
- Родственный класс уже встречался в проекте: bugs 48/63 (SIGABRT вокруг поверхностей превью),
  из-за которых на пути гибели эфира `startPreview(tv)` был заменён на `restorePreviewIfDetached()`.

**НЕ известно (не выдумывать):**
- что именно продолжало рисовать в течение 22 минут простоя — Compose-анимация, `postDelayed` рендер-луп
  композитора или превью-`TextureView`;
- было ли в этот момент погашение экрана/сворачивание (в логе приложения записей нет — см. дефект
  наблюдаемости ниже);
- воспроизводимость: за прогон Ш0 (7 минут эфира + заморозки + стоп) краш НЕ повторился.

## 🔴 Сопутствующий дефект наблюдаемости (важнее самого бага)

**FileLogger теряет хвост при аварийном завершении.** Последняя запись в
`kcam_2026-07-28.log` — `20:46:58`, а процесс жил до `21:08:21`. То есть **22 минуты перед крашем
не сохранены**: буфер не был сброшен на диск, а SIGABRT убивает процесс без шанса дописать.

Следствие для всей работы над багами: любой краш-репорт от Криника приходит БЕЗ последних минут
контекста — самых нужных. Это ровно тот случай, когда «форензика есть» оказывается иллюзией.

Кандидаты в лечение (выбрать по замеру, не вслепую):
1. flush по таймеру (например, раз в 2–5 с) — простое, но чаще пишет на диск;
2. flush на `onPause`/`onStop` и при переходе состояний стрима — дёшево, но не спасает от краша в простое;
3. `Thread.setDefaultUncaughtExceptionHandler` не поможет — SIGABRT не проходит через JVM-обработчик;
   нужен именно периодический flush.

## План

- [ ] **Ш1. Сначала наблюдаемость** (иначе следующий краш опять придёт без контекста): периодический
      flush FileLogger + запись фактов «экран погас / приложение в фоне» (`ProcessLifecycleOwner`,
      `ACTION_SCREEN_OFF`) — это те самые события, которых сейчас не хватает для диагноза.
- [ ] **Ш2. Инвентарь класса** (канон «закрывай класс, а не экземпляр»): найти всё, что продолжает
      рисовать после ухода поверхности — рендер-луп композитора (`postDelayed`, `FRAME_MS`),
      превью-`TextureView`, Compose-анимации, живущие вне видимости.
- [ ] **Ш3. Попытка репро:** долгий простой (20–30 мин) после остановки эфира с погашенным экраном,
      затем то же со сворачиванием приложения. Прогон под непрерывным logcat в файл.
- [ ] **Ш4.** Фикс по найденной причине + гард, проверенный на сломанной версии
      (`BUG_FIXING_FRAMEWORK.md` → Гарды).

# Bug 68 — Переключение сцен переинициализирует UVC (чёрный/заглушка Pico+)

> Заведён: 2026-07-25 (Криник, живьём). Приоритет: ВЫСОКИЙ — ломает бесшовность переключения сцен.
> Статус: ✅ ИСПРАВЛЕН и проверен живьём.

## Симптом (со слов Криника)

«Переключаюсь между Сцена 1 и Сцена 2 — обе с фидом Pico+ — частенько на Сцене 2 чёрный прямоугольник
или заглушка Pico+, лишь изредка видео стартует. Плохая реализация переключения слоёв.»
Уточнение видения: слои должны быть ИМЕНОВАННЫМИ и переиспользуемыми — один слой с Pico+ можно шарить на
две сцены для бесшовного переключения БЕЗ переинициализации Pico (или сделать два разных слоя с Pico).

## Root cause

Переключение сцены (`switchScene`) меняет набор слоёв → мост `:app` (`MainScreen` LaunchedEffect)
пересоздаёт опенеры камер. Для UVC/встроенной это значило `old.close()` + `new.open()` ФИЗ-камеры даже
когда НОВЫЙ слой целит в ТОТ ЖЕ физ-источник (Pico+). Переинициализация AUSBC (`closeCamera`/`openCamera`
на `/dev/bus/usb/...`) ~1.5с и флакая → чёрный прямоугольник / заглушка, редко успевает стартовать.

Лог (до фикса, переключение): `UVC camera closed (layer)` → `CameraSlot RECREATED` → `UVC camera opened`
→ `UsbDeviceRepository Camera closed/opened /dev/bus/usb/001/005` на КАЖДЫЙ switch.

## Фикс

`RtmpStreamer.setCameraOpener` — гард бесшовности: если на слой приходит НОВЫЙ опенер с ТЕМ ЖЕ `sourceKey`
(та же физ-камера), а старый продюсер ещё ЖИВ (`old.isAlive`) — НЕ закрываем/не переоткрываем: оставляем
живого продюсера, его слот продолжает получать кадры без разрыва. Смена физ-источника ИЛИ мёртвый продюсер
— обычный путь (close+reopen). Так две сцены на одном Pico+ переключаются бесшовно, независимо от того,
шарит юзер слой или сделал два разных слоя (физ-источник один → камера остаётся живой).

## Приёмка (наблюдение, 2026-07-25, живьём, Pico+)

- **Одинаковые сцены** (обе `[camera=uvc]`): 5+ переключений подряд — НИ ОДНОГО `Camera closed/opened
  /dev/bus/usb` (эффект даже не перезапускается — тот же ключ). Фид живой (скриншот: комната в движении).
- **Разные по структуре сцены** (`[camera=uvc]` ↔ `[camera=uvc, camera_1=virtual]`): лог
  `setCameraOpener[camera]: тот же физ-источник (uvc:1005) и продюсер жив — БЕЗ переоткрытия (bug 68)`;
  базовый Pico+ НЕ переоткрывается, лишний слой virtual появляется/исчезает штатно. Фид базы не рвётся.
- 0 крашей, приложение живо.

## Не входит (отдельная фича — видение Криника)
**Именованные переиспользуемые слои** (OBS-подобные шаренные источники: создать слой с Pico+ ОДИН раз,
ссылаться из нескольких сцен). Текущий фикс даёт бесшовность на уровне ФИЗ-источника (результат тот же для
юзера), но МОДЕЛЬ «слой = именованная сущность, сцена ссылается» — это Фаза 2 эпика сцен, через интервью
(шарить/независимо, UI создания/переиспользования, семантика общей правки). Зафиксировано в plans/18.

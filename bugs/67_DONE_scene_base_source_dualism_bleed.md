# Bug 67 — Источник базового слоя протекает между сценами (дуализм DeviceManager vs сцена)

> Заведён: 2026-07-25 (Криник, живьём после Фазы 1 профилей сцен). Приоритет: ВЫСОКИЙ — ломает саму
> ценность сцен (независимость). Статус: ✅ ИСПРАВЛЕН и проверен живьём.

## Симптом (со слов Криника)

«Слой должен быть именованным и относиться к сцене. Настраиваю Сцену 1 → устройство захвата 1 (селфи),
Сцену 2 → устройство захвата 2 (вебка); при переключении сцен должен бесшовно получать соответствующий
фид. А по факту: поменял источник в ОДНОЙ сцене — изменился источник и в ДРУГОЙ. Нонсенс! Баг! Недоделка.»

## Root cause — ДУАЛИЗМ владения источником базового слоя

Источник **базового** слоя `id="camera"` жил в ГЛОБАЛЬНОМ `@Singleton DeviceManager._activeVideoSource`,
а НЕ в сцене. Раздвоение (подтверждено картой кода + наблюдением):
- **UI-пикер** (`MainScreen`): для `camera` писал `deviceManager.selectVideoSource(...)` (глобал); для
  доп. слоёв — `setCameraLayerSource` (scene.source). → база не попадала в сцену.
- **Рендер** базы шёл через `LaunchedEffect(activeSource…)` (глобал), а доп. слои — по `scene.layers[].source`.
- **`switchScene`** не ресинкал глобал (у `RtmpStreamer` нет ссылки на `DeviceManager`).
- **Харнес** `select-source`/`device-camera`/`virtual-camera` тоже писали глобал.

Следствие: смена источника базы в любой сцене меняла глобал → протекала во ВСЕ сцены; переключение сцен
не меняло фид базы; снапшот сцены всегда писал базу как `none`. Дуализм был явно помечен в `plans/18` как
задача Фазы 1 («устранить дуализм: источник базы ЖИВЁТ в сцене»), но при реализации Фазы 1 не закрыт.

**Наблюдение (БД до фикса):** все сцены `base camera source = none`, хотя ставились разные источники.

## Фикс — базовый слой стал scene-owned (Вариант 1 «устранить дуализм»)

`MainScreen.kt`:
1. Две реконсиляции опенеров ОБЪЕДИНЕНЫ в одну по `scene.layers[].source` для ВСЕХ слоёв-камер, включая
   базовый (спец-`LaunchedEffect(activeSource)` для базы удалён).
2. UI-пикер источника: убран спец-кейс `camera` → всегда `setCameraLayerSource(layerId, …)` (в сцену).
3. Подсветка текущего источника (`sourceIdOf`): база тоже из сцены, не из `activeSource`.
4. **Bootstrap-сев проактивности:** базовый слой без источника (`None`) авто-засевается лучшим доступным
   (авто-выбор DeviceManager), но пишется В СЦЕНУ (`setCameraLayerSource("camera", …)`) — остаётся
   пер-сценовым, не протекает. Идемпотентно (сеет только None). «Воткнул вебку → сразу видно» сохранён.

`MainActivity.kt`: харнес `select-source`/`device-camera`/`virtual-camera` теперь пишут базу слоя
`"camera"` В СЦЕНУ (не в глобальный DeviceManager). `virtual-camera` сохраняет управление доступностью
виртуалки (DevSettings) + пишет сцену.

`switchScene` менять не пришлось: база теперь реконсилится из сцены → переключение меняет фид корректно.

## Приёмка (наблюдение, 2026-07-25, живьём, Piko+ + виртуалка)

- **БД пер-сценово:** сцене 9 базу→`virtual`, сцене 10 базу→`uvc` → в БД `scene 9=virtual, scene 10=uvc`
  (раздельно).
- **Анти-протечка:** правка источника сцены 9 НЕ изменила источник сцены 10 (остался `uvc`).
- **Визуальное переключение:** switch на сцену 10 → **вебка** (комната); switch на сцену 9 → **тест-паттерн
  виртуалки** (VIRTUAL CAM · frame N). Фид базы меняется под сцену — ровно требование Криника.
- Сборка BUILD SUCCESSFUL; крашей нет.

## Известное ограничение (решение без владельца)
Явный выбор «Нет источника» на БАЗЕ при активном устройстве будет пере-засеян bootstrap'ом (истинно
пустая база = отдельная фича). Доп. слои можно оставлять пустыми свободно. Спросить Криника, если нужна
истинно-пустая база («BRB»-сцена без камеры).

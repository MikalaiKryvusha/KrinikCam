# Bug 70 — На бейдже ЗАПИСЬ битрейт периодически проваливается в «0,0 Mbps»

> Заведён: 2026-07-25 (побочная находка при приёмке bug 45 — видна на покадровой нарезке видеозахвата
> экрана). Приоритет: НИЗКИЙ (косметика индикации, на сам файл записи не влияет).

## Симптом

Во время записи в файл статус-пилюля показывает битрейт скачками: `0,0 → 1,9 → 0,0 → 4,2 → 0,0 …`
вместо плавного значения. На эфире (RTMP) дефект не проявляется.

## Репро (детерминированное, без вебки)

1. `node tools/ui.mjs cmd select-source virtual`, затем `cmd stream-to-file on`, затем `cmd go-live 720`.
2. Снять видеозахват экрана: `adb shell screenrecord --time-limit 5 /sdcard/x.mp4`, нарезать кадры
   (`ffmpeg -i x.mp4 -vf fps=6 f_%02d.png`) и посмотреть текст пилюли покадрово.
3. Наблюдать чередование ненулевого битрейта и «0,0 Mbps» примерно раз в секунду.

## Root cause (по чтению кода, требует подтверждения замером)

Двое пишут в одно поле `StreamState.Live.bitrateKbps`, и они не согласованы:

- `recordListener.onNewBitrate` (`RtmpStreamer`) — даёт РЕАЛЬНЫЙ битрейт записи (со сглаживанием EMA,
  bug 53);
- секундный тикер `startLiveTicker` (idea 37) на каждом тике пересчитывает
  `bitrateKbps = outputStates.filter { phase == Live }.sumOf { bitrateKbps }`. При ЗАПИСИ RTMP-выходов
  нет вовсе → `outputStates` пуст → сумма = **0**, и тикер затирает значение от записи.

То есть тикер по построению рассчитан на эфир (сумма по выходам) и не учитывает, что при записи
источник истины — колбэк `RecordController`.

## План фикса (дешёвый)

1. В тикере не затирать битрейт, когда RTMP-выходов нет (запись): при пустом `outputStates` сохранять
   текущее значение `bitrateKbps` вместо суммы нуля. Обновлять при записи только `durationMs`.
2. Приёмка: та же покадровая нарезка — значение битрейта меняется плавно и не проваливается в 0,0;
   на эфире (полигон/кривой URL) агрегат по выходам не сломан.

## Связи

Пре-существующий дефект (тикер жил так с idea 37 / bug 53), НЕ регресс bug 45 — обнаружен при его
приёмке, потому что честная индикация заставила присмотреться к пилюле покадрово. Тот же файл:
`feature/streaming/.../rtmp/RtmpStreamer.kt` (`startLiveTicker`, `recordListener.onNewBitrate`).

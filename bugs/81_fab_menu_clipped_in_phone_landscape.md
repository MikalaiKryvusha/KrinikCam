# Bug 81 — в ландшафте телефона ПОСЛЕДНИЙ пункт FAB-меню обрезан краем экрана и недостижим

**Статус:** 🔴 ОТКРЫТ — воспроизведён с числами, фикс не делался
**Версия:** 0.8 (63)-debug
**Устройство:** Samsung Galaxy A51 (`R58N615KXZZ`), Android 13 / SDK 33, **ландшафт**, `font_scale=1.1`
(обычная настройка Криника, НЕ искусственная теснота)
**Найден:** 2026-08-02, защищённый цикл — плановый проход по классу «UI принимался только на планшете»
**Класс:** тот же, что `bugs/78` (модалка сцены обрезала чипы) и два его близнеца в
`StreamLayersOverlay`. Класс НЕ выработан: вот четвёртый случай.

---

## 1. Симптом

В ландшафте телефона выпадающее меню кнопки «Меню» (FAB) не помещается по высоте: видны пять пунктов
(**В эфир · Запись · Фото · Платформы · Кодер**), а **шестой обрезан краем экрана** — до него нельзя
ни дотянуться, ни доскроллить. Прокрутки у меню нет: свайп по нему попадает в подложку и ЗАКРЫВАЕТ
меню, а не листает.

Дополнительно: плашки всех пунктов упираются правым краем ровно в границу экрана
(`bounds` правый = 2312 при ширине экрана 2312), то есть запаса нет и текст стоит впритык.

## 2. Репро (стабильно, 2 прогона из 2)

```bash
export ADB_DEVICE=192.168.1.41:5555
node tools/ui.mjs restart debug          # A51
node tools/ui.mjs orient landscape
node tools/ui.mjs tap "Меню"
node tools/ui.mjs dump
```

## 3. Числа (это и есть доказательство, а не впечатление)

Экран `2312×1041`. Высота нормального пункта — **129 px**; у последнего — **29 px**:

| Пункт | bounds | высота |
|---|---|---|
| В эфир | `[1981,105][2312,234]` | 129 |
| Запись | `[1981,250][2312,379]` | 129 |
| Фото | `[1981,395][2312,524]` | 129 |
| Платформы | `[1981,540][2312,669]` | 129 |
| Кодер | `[1981,685][2312,814]` | 129 |
| **(шестой, без текста)** | **`[1981,830][2312,859]`** | **29** ← обрезан |

Трактовка высоты 29 — по **EXP-0051**: `uiautomator dump` отдаёт границы, ОБРЕЗАННЫЕ по видимой
области родителя, поэтому аномально малая высота означает «элемент уехал за край», а не «элемент
маленький». Проверка прокруткой (тот же урок) выполнена: прокрутки нет, свайп закрывает меню.

При `font_scale=1.5` картина хуже: пунктов видно четыре, обрезаны два, и это подтверждается глазами
на скриншоте (плашки уходят за правый край).

**Скриншот (font_scale 1.5, ландшафт):** `bugs/assets/81_fab_menu_landscape.jpg` — видно, что
плашки уходят за правый край, а нижние пункты срезаны.

## 4. Почему это важнее, чем «мелочь вёрстки»

Класс уже дал четыре дефекта (`bugs/78` + два близнеца + этот). Общая причина одна: **вёрстка
рассчитана на планшет, где высоты хватает всегда**, и на телефоне в ландшафте (высота 1041 против
2400 в портрете) списки перестают помещаться. Пока не закрыт КЛАСС, а не экземпляры, дефекты будут
всплывать по одному — ровно то, чего канон велит избегать («закрывай класс, а не экземпляр»).

## 5. План

- [ ] **Ф1. Инвентарь класса ПЕРЕД фиксом.** Грепом найти ВСЕ вертикальные списки/меню/колонки без
      `verticalScroll` и с фиксированными отступами: FAB-меню, панели, оверлеи, экраны настроек.
      Список — в этот документ. Судить фикс ПО СТРОКАМ инвентаря.
- [ ] **Ф2. Фикс формой, а не заплаткой:** прокрутка у контейнера меню (как в `bugs/78`), чтобы
      класс не мог разъехаться снова.
- [ ] **Ф3. Гард, доказанный мутацией:** проверка «в ландшафте видны ВСЕ пункты меню» — прогнать на
      сломанной версии (без прокрутки) и увидеть красное, только потом верить зелёному
      (`BUG_FIXING_FRAMEWORK.md` → Гарды; приём тесноты — EXP-0049, `font_scale`).
- [ ] **Ф4. Приёмка** на A51 в ландшафте при `font_scale` 1.1 И 1.5: все пункты достижимы тапом.

## 6. Решения, принятые без владельца

1. Диагноз «обрезано, а не мало» взят из EXP-0051 и подтверждён проверкой прокрутки — это не
   догадка по одному числу.
2. Баг заведён, но НЕ чинился в этом цикле: до конца защищённого прогона оставалось ~25 минут, а
   фикс класса требует инвентаря (Ф1) — начинать его в остаток времени значило бы оставить работу
   на середине.

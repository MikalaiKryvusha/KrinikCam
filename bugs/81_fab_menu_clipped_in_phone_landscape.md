# Bug 81 — в ландшафте телефона у FAB-меню не видно, что список ПРОКРУЧИВАЕТСЯ (пункт «Настройки» за краем)

**Статус:** 🟡 ОТКРЫТ, тяжесть ПОНИЖЕНА после перепроверки — это UX-дефект видимости, а НЕ потеря
доступа. Первая редакция документа утверждала «пункт недостижим»; это оказалось **ложной находкой**
(разбор в §4).
**Версия:** 0.8 (65)-debug
**Устройство:** Samsung Galaxy A51 (`R58N615KXZZ`), Android 13 / SDK 33, **ландшафт**,
`font_scale=1.1` (обычная настройка Криника)
**Найден:** 2026-08-02, защищённый цикл — проход по классу «UI принимался только на планшете»

---

## 1. Симптом (уточнённый)

В ландшафте телефона FAB-меню показывает пять пунктов из шести: **В эфир · Запись · Фото ·
Платформы · Кодер**, а **«Настройки» остаются за нижним краем**. Список прокручивается, и пункт
достижим — но **ничто на экране об этом не сообщает**: ни срезанного «наполовину» ряда, ни полосы
прокрутки, ни затухания у края. Пользователь видит пять аккуратных пунктов и имеет все основания
считать, что это весь список.

В портрете проблемы нет — там помещаются все шесть.

## 2. Репро

```bash
export ADB_DEVICE=192.168.1.41:5555
node tools/ui.mjs orient landscape
node tools/ui.mjs tap "Меню"
node tools/ui.mjs dump                          # 5 пунктов; шестой высотой 29 px = обрезан краем
node tools/ui.mjs swipe up 0.25 --at=2147,600   # прокрутка РАБОТАЕТ → появляются «Настройки»
```

## 3. Числа

Экран `2312×1041`. Высота нормального пункта — **129 px**, у шестого — **29 px**
(`[1981,830][2312,859]`), то есть он обрезан границей видимой области. После прокрутки он виден
целиком, а за край уходит «В эфир».

Арифметика причины: в ландшафте доступно ≈ 1041 px ≈ 396 dp, из них `top=40dp` + `bottom=108dp`
(место под сам FAB) = 148 dp съедено, остаётся ≈ 248 dp; шесть пунктов с отступами — около 330 dp.
Не помещается по построению. Ограничение `heightIn(max = 560.dp)` тут ни при чём — упираемся в
физическую высоту экрана.

**Скриншот** (font_scale 1.5, ландшафт): `bugs/assets/81_fab_menu_landscape.jpg`.

## 4. 🔴 Как я ошибся в первой редакции (урок дороже самого бага)

Первая редакция утверждала: «прокрутки нет, свайп закрывает меню, пункт НЕДОСТИЖИМ». Проверка
опровергла это дважды:

1. **В коде прокрутка ЕСТЬ** — `FloatingPanelMenu` (`:76`) имеет
   `.verticalScroll(rememberScrollState())`. Я заявил её отсутствие, не открыв файл контейнера.
2. **Свайп на 800 мс список прокручивает.** Мой первый свайп был на 300 мс — Android распознал его
   как ТАП, тап попал в закрывающий скрим, меню закрылось. Я принял это за «прокрутки нет».

Это **повторение EXP-0051**, причём я цитировал этот урок в этом же документе — то есть знал его и
всё равно наступил. По канону KAIF 2.1 повторившийся урок обязан стать МЕХАНИЗМОМ, а не третьим
напоминанием:

**`mechanized: tools/ui.mjs swipe`** — (а) дефолт длительности поднят `300 → 700 мс` (короткий жест
трактуется системой как тап); (б) добавлен `--at=x,y`, потому что свайп по ЦЕНТРУ экрана в оверлее
попадает в скрим и закрывает панель — прокрутить боковое меню без этой опции было нельзя в принципе.
Проверено на живом устройстве: `swipe up 0.25 --at=2147,600` прокручивает меню и открывает
«Настройки».

- [x] **Ф1. Инвентарь класса СНЯТ** (греп `Column(` без `verticalScroll`/`LazyColumn`):

      | Файл | Column | Прокрутка | Риск |
      |---|---|---|---|
      | `ui/overlay/FloatingPanelMenu.kt` | ×1 | **ЕСТЬ** | 🟡 прокрутка есть, но НЕ ВИДНА — этот баг |
      | `ui/screens/MainScreen.kt` | ×2 | нет | 🟡 статус-пилюля, контент небольшой |
      | `ui/screens/DevMenuScreen.kt` | ×1 | нет | 🟡 4 пункта: сегодня влезает, при росте — обрыв |
      | `ui/overlay/RotationMenu.kt` | ×1 | нет | 🟡 список пунктов той же формы |
      | `ui/overlay/StandbyPlaceholder.kt` | ×2 | нет | 🟢 фиксированный контент, не растёт |

- [ ] **Ф2. Сделать прокрутку ВИДИМОЙ** в `FloatingPanelMenu`. Чем именно — решает Криник (класс
      ВКУСА → мокапы): полоса прокрутки · затухание-градиент у края · намеренно «недорезанный» ряд,
      который сам показывает продолжение.
- [ ] **Ф3. Прокрутку — остальным меню класса** (`RotationMenu`, `DevMenuScreen`): у них её нет
      вовсе, и при росте числа пунктов они получат НАСТОЯЩУЮ потерю доступа, а не только видимости.
- [ ] **Ф4. Гард, доказанный мутацией:** проверка «в ландшафте достижимы ВСЕ пункты меню» — снять
      прокрутку, увидеть красное, и только потом верить зелёному.

## 6. Решения, принятые без владельца

1. **Тяжесть понижена** после перепроверки: потерян не доступ, а видимость. Оставить прежнюю
   формулировку значило бы держать в беклоге пугающий и неверный документ.
2. **Способ сделать прокрутку видимой НЕ выбран агентом** — вопрос вкуса, идёт Кринику мокапами.
3. Механизация урока в `ui.mjs` сделана сразу и без спроса: это инструмент агента, а не продукт.

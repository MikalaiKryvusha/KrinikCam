## Боль, которую решает

Сейчас снаружи приложение управляется одним каналом — DEBUG-only broadcast `com.kriniks.kcam.CMD`
(`tools/ui.mjs cmd …`, Idea 22): только по ADB, только из debug-сборки, без ответа (fire-and-forget,
результат читается из логов). Агенту и автоматизации тестирования нужен канал С ОТВЕТОМ и без
провода, а ИИ-агенту — родной MCP-интерфейс к приложению.

## Чем проверим, что сработало (черновик критериев — уточнить в плане)

- ADB: команда возвращает структурированный ответ (не только строку в логе).
- HTTP: с ПК в той же сети `GET /status` отдаёт состояние приложения (сцена, источник, эфир, битрейт).
- MCP: Claude Code видит инструменты KrinikCam и выполняет ими сценарий смоука без `ui.mjs`.

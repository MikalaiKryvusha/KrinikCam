# План 18 · Фаза 2 — Бесшовное переключение сцен В ЭФИРЕ

> Часть эпика [[idea 40]] / карта — [18_scene_profiles.md](18_scene_profiles.md). Стартует ПОСЛЕ Фазы 1.
> 📝 Набросок: детализируется при старте. Интервью не требуется (чисто техническая зона).

## Цель
Переключение активной сцены во время стрима — **без разрыва эфира, без чёрного кадра/мельтешения, 0 крашей**.
Ключевая OBS-фича: сцена «камера» → сцена «экран» → сцена «BRB» прямо в прямом эфире.

## Что шипается
- `setActiveScene(id)` работает и в состоянии `Live`: `applySceneLayers()` уже отдаёт слои композитору
  live (`CompositorVideoSource.setLayers`) — энкодер НЕ пересоздаём.
- Камеры переоткрывать ТОЛЬКО при РЕАЛЬНОЙ смене физ-источника: переиспользовать логику
  `sourceKey`/первичный-зеркало (bug 58) и грейс/отложенный re-attach (bug 62/#3). Слои с тем же
  устройством между сценами — не дёргать (шаринг фида цел).
- Разрешение/битрейт менять в эфире НЕЛЬЗЯ (ломает RTMP, [[idea 06]]) — сцены не меняют разрешение
  холста, только состав слоёв; проверить, что переключение не триггерит ресайз/поворот.

## Опора
`applySceneLayers` (live setLayers), `cameraLayerMirrors`/`layerSourceKeys`/`openedLayers` (bug 58),
`reopenDeadCameras`/грейс (bug 62/64), полигон `rtmp-server.mjs` + `go-live-rtmp`.

## Приёмка (харнес, полигон)
go-live → переключить сцену 5× → эфир не рвётся (сервер держит publish), без чёрного/заглушки-мельтешения,
0 крашей; стоп-стресс как в bug 63. Живая сверка Криника на реальном ключе (ДЗ-05).

## Риски
GL/камер-lifecycle (семья bug 58/62/63) — самая хрупкая зона; открытие/закрытие камер при смене сцены
должно идти строго через существующие гарды (`openedLayers`, primary/mirror). Аудио-дорожка непрерывна.

## ✅ Сделано 2026-07-25 — ПЕРЕХОДЫ СЦЕН + удержание кадра (заказ Криника в чате)

Криник в чате: «давай сделаем переходы между сцен — чтобы в модалке редактирования сцены был выбор типа
перехода и его длительность» + жалоба про чёрный прямоугольник при переключении вебка→селфи (`bugs/71`).
Обе задачи закрываются ОДНОЙ машинерией — снимком старой сцены.

- **Модель:** у сцены появились `transitionType` + `transitionDurationMs` (Room **v5→v6**,
  `MIGRATION_5_6`, аддитивно с дефолтами `FADE`/400 мс; schema 6.json в git). Домен —
  `SceneTransition { NONE, FADE, SLIDE }` + границы 100…3000 мс. Переход принадлежит сцене, НА которую
  переключаются (семантика OBS).
- **UI:** диалог переименования расширен до **модалки редактирования сцены** — имя + чипы типа перехода
  («Мгновенно / Плавно / Выезд») + чипы длительности (0.2/0.4/0.8/1.5 с; для «Мгновенно» неактивны).
  Строки EN/RU.
- **Композитор:** `beginTransition(type, ms)` снимает ВЕСЬ композит старой сцены в свой FBO ДО отдачи
  новых слоёв; рендер-цикл держит снимок, пока новая сцена не готова (каждый первичный слот-камера
  забрал ≥2 кадра — видимый кадр отстаёт на один из-за пинг-понга снапшота), кап 3 с; затем играет
  эффект: FADE — кросс-фейд, SLIDE — старая сцена уезжает влево, NONE — мгновенная склейка, но уже по
  ГОТОВОЙ сцене. Переход рисуется ДО прохода 2 → корректно крутится вместе с холстом.
- **Побочный эффект по замыслу:** чёрный прямоугольник при смене физ-камеры между сценами исчезает
  (`bugs/71`) — держится последний кадр прошлой сцены.

**Проверено живьём:** миграция на реальной БД Криника (3 сцены целы); переключение вебка→селфи:
`снят кадр старой сцены` → `новая сцена готова через 611мс` → `эффект FADE 400мс` → `завершён`.
🟡 Визуальная сверка финальной доводки («2 кадра») — за Криником: планшет был занят им (DRM-контент
блокирует `screenrecord`).

**Остаток фазы (не сделано этим заходом):** переключение сцен ПОД ЭФИРОМ на полигоне (стресс 5×,
непрерывность publish), стоп-стресс как в bug 63.

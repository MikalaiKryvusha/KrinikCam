# `plans/` — детальные планы работ

Детальные планы отдельных кусков работы: шагов генплана, конкретных фич, идей, багов, исследований,
процедур. Высокоуровневый маршрут — **`MASTER_PLAN.md`** (корень проекта); здесь лежат «приближенные»
планы, реализующие его шаги. Один план — один файл.

**Кринику (владельцу):** писать сюда не обязательно — планы обычно пишет агент. Можешь положить свой
план, если хочешь направить, КАК что-то делать. Читай их, чтобы видеть замысел агента до исполнения.

**ИИ-агенту:** перед нетривиальной работой напиши сюда короткий план и следуй ему. Каждый план
ОТКРЫВАЕТСЯ вектором цели + критериями приёмки — по `REQUIREMENTS_FRAMEWORK.md`; по ходу работы они
уточняются (KAIF 2.2). Сразу после H1 — линтуемая шапка-мета: **Создан:** · **Родитель:** ·
**Статус:** (с вехами) · **Вовне:** (`AGENT_GUIDE.md` → «Шапка-мета документа»). Новые планы нумеруй
(`NN_<name>.md`); исторические файлы фаз (`phase_*.md` и т.п.) оставлены с их именами — не переименовывай.
Завершённый и проверенный план получает тег `DONE` в имени (`git mv NN_x.md NN_DONE_x.md`) плюс секцию
статуса. Справочные документы (worklog'и, референсы — не закрываемая задача) тегом DONE не помечаются.

**Именование — эпик виден в беклоге по имени файла (KAIF 2.9).** Тяжёлая, составная, долгая работа
планируется **эпиком** (`/plan-epic`), и его файл несёт пометку: **`NN_EPIC_<имя>.md`**. Файл эпика
держит пофазовое архитектурное описание дорожной карты — *и никакой операционной детализации*.
Детализация живёт у **детей**: по операционному плану на фазу, и каждый ребёнок называет родителя в
собственном имени — **`NN_epicMM_<фаза>_<имя>.md`** (`MM` — номер эпика). Детализируется только
ближайшая фаза; план фазы N+1 пишется на закрытии фазы N. Конвенция действует ВПЕРЁД: старые планы
(например, эпик настроек камер `plans/24` и его фаза `plans/25`) не переименовываются — их номера уже
процитированы по всей истории.

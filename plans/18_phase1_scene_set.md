# План 18 · Фаза 1 — Набор именованных сцен + менеджер в радиалке

> Часть эпика [[idea 40]] / карта — [18_scene_profiles.md](18_scene_profiles.md). Стартует ПОСЛЕ Фазы 0.
> 📝 Набросок: детализируется при старте (с учётом уроков Ф0). Перед стартом — **интервью (развилка 3)**.

## Цель
Держать НЕСКОЛЬКО именованных сцен и переключаться между ними (пока БЕЗ требования бесшовности в эфире —
это Фаза 2). FAB «Сцены» из Ф0 становится настоящим менеджером.

## Что шипается
- Room-таблица `scene_profiles(id, name, snapshotJson, createdAt, updatedAt)` + DAO (CRUD, `observeAll`) —
  по образцу `EncoderProfileEntity/Dao`. Бамп БД v4→v5 + `MIGRATION_4_5` (создать таблицу). Схема в git.
- Активная сцена — id в DataStore (как `active_profile_id`; ключ `active_scene_id`).
- Автосейв Ф0 переезжает с «одной текущей» на **активную запись** таблицы (debounce → upsert активной).
- FAB-радиалка (компонент по образцу `FloatingRadialMenu`): веер существующих сцен (тап = **переключить**
  активную) + действия «Новая / Дублировать / Переименовать / Удалить».
- Переключение: `setActiveScene(id)` → загрузить снапшот → `_scene.value = …` → `applySceneLayers()`.
  Дублирование оверлеев: копировать PNG-файлы под новые layerId (не шарить путь между сценами).

## Опора
`EncoderProfilesOverlay` (CRUD-менеджер), `FloatingRadialMenu` (радиалка), `ProfilesRepository`
(паттерн Room+DataStore+fallback), `SceneSnapshotDto/Mapper/ImageOverlayStore` из Ф0.

## Интервью (развилка 3, [[idea 40]])
Сколько сцен показывать веером радиалки? Нужен ли отдельный полный список-менеджер (как у платформ) при
многих сценах? Как выглядит переименование (инлайн/диалог)? Дефолтные имена новых сцен?

## Приёмка
Создать 2 сцены, переключаться туда-обратно из радиалки → композит меняется корректно; сцены переживают
рестарт (каждая своя); удаление активной снимает выбор (fallback на первую/дефолт, как у профилей кодера).

## Риски
Миграция Room (не потерять данные — destructive-фолбэка нет, забытая миграция роняет старт); копирование
оверлеев при дублировании; чистка файлов при удалении сцены.

## Статус
✅ **СДЕЛАНО и проверено живьём (2026-07-25).** Интервью (развилка 3) закрыто — `interview_010`
(панель-список, полный CRUD, диалог + «Сцена N»).

### Что реализовано
- **Data (`:data:profiles`):** `SceneProfileEntity`/`SceneProfileDao` (таблица `scene_profiles`), БД
  v4→**v5** + `MIGRATION_4_5` (аддитивная, schema `5.json` в git), `provideSceneProfileDao`, DataStore-ключ
  `active_scene_id`.
- **Repo (`:feature:streaming`):** `SceneProfileRepository` — observeScenes/activeSceneId, ensureSeeded
  (разовый сев первой сцены из легаси Ф0-снапшота — работа Криника не теряется), loadActive/saveActive
  (автосейв активной записи), create/duplicate/rename/delete/switch. **Изоляция оверлеев по сцене**:
  `overlays/scene_<id>/` (namespace) — иначе одинаковые layerId между сценами коллидят и pruning одной
  удаляет файлы другой (`ImageOverlayStore` +namespace-методы).
- **Стример:** restore АКТИВНОЙ сцены на старте + автосейв её (debounce 400мс) вместо «одной текущей»;
  публичные `switchScene/createNewScene/duplicateScene/renameScene/deleteScene` + потоки `scenesList`/
  `activeSceneId`. Флаш текущей перед переключением. Удаление ПОСЛЕДНЕЙ сцены авто-создаёт дефолт
  (никогда не «ноль сцен»).
- **UI:** `ScenesManagerOverlay` (панель-список): сцены (тап=переключить, активная подсвечена) +
  Переименовать(диалог)/Дублировать/Удалить(подтверждение) + «＋ Новая сцена». Строки EN+RU.
- **Харнес:** `ui.mjs cmd scene-new|scene-list|scene-switch|scene-duplicate|scene-rename|scene-delete`.

### Приёмка (наблюдение)
Миграция v4→v5 без краша; сев из Ф0 (2 слоя сохранены); CRUD (создание, нумерация «Сцена N»,
переключение, дубль, удаление); **персист через рестарт** (активная восстановлена, все сцены целы);
delete active→fallback, delete последней→авто-дефолт; **изоляция оверлеев** (scene_4 имеет PNG,
scene_5 пуст; switch туда-обратно сохраняет per-scene); UI-панель рендерится и переключает живьём.
Побочно найден+исправлен **bug 66** (краш опенера Camera2 при переключении — гонка async-колбэка).

### Решения, принятые без владельца
- **Удаление ПОСЛЕДНЕЙ сцены → авто-создание дефолтной** (не «ноль сцен», не пустой чёрный экран).
  Альтернатива (реseed из легаси Ф0) отвергнута: набор перестаёт пустеть → предсказуемее. Спросить, если
  Криник захочет иное поведение «удалил всё».
- **Подтверждение удаления** сцены диалогом (защита от случайной потери) — интервью явно не требовало,
  но потеря сцены дорогая. Легко убрать, если мешает.
- **Порядок сцен** — по id (создания); drag-reorder НЕ делал (не запрошен).
- Легаси Ф0-снапшот (`kcam_scene` DataStore) НЕ удаляю после сева — остаётся как страховка; плоские
  оверлеи легаси тоже не трогаю (namespace-копии — источник правды).
